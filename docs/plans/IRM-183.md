# IRM-183: Unblock policy: drop the fork-PR step, limit PR creation to collaborators

Every PR's `policy` check fails since PR #111 (IRM-128): the "Refuse fork PRs" step runs `.github/scripts/fork-pr.sh` before the repository is checked out, so it exits 127. `policy` runs `main`'s copy of the workflow, so #111 passed on the old copy and no PR can fix it.

## Progress

- Deleted the step, `fork-pr.sh`, `fork-pr.test.sh`, both fixtures and the Makefile line. `git grep fork-pr -- .github Makefile` finds nothing; the remaining mention is IRM-128's finished plan file.
- Guardrails 2.12 records the "Collaborators only" PR setting and why the step went.
- `make check-repo` passes (exit 0), with ast-grep 0.51.0 and gitleaks 8.30.1 installed in the session.

## Decisions

- Delete instead of moving the step below the checkout: no fork has opened a PR, and `fix-rounds` already skips PRs whose head isn't this repository (policy.yml).
- The owner sets Pull requests → "Collaborators only" in the repository settings and admin-merges this PR, since `main`'s broken `policy` judges it (owner, 2026-10-25).
