# IRM-130: Harden BankID login: explicit mode, throttled start, start-up checks, session lifetimes

Full description and Decisions: https://linear.app/petters/issue/IRM-130

## Progress

- `checkBankidConfig` refuses a missing `BANKID_MODE` or `PUBLIC_URL` when `APP_ENV` is test or production (`npx vitest run src/server/auth`).
- Sessions: 24 h absolute and 1 h idle for web and app, no sliding renewal, `last_used_at` at most once a minute (`npx vitest run src/server/session.server.test.ts`).
- `POST /api/v1/auth/bankid/start` counts `login_started` audit rows per /24 (20 per 15 min), answers 429 and logs `rate_limited` with an HMAC key (`npx vitest run src/server/login.server.test.ts`).
- Root CAs committed in `bankid-ca.server.ts` from cdn.bankid.com/pki/bankid/ (read 2026-10-25), fingerprint test; `BANKID_ROOT_CA_PEM` no longer read.
- Same-device panel shows the QR hint (`e2e/login.spec.ts`).
- `docs/privacy/records.md` updated.

## Decisions

- Throttle: 20 starts per 15 minutes per network, judgement.
- Follow-up outside this PR: IRM-93's app flow text, and the `BANKID_ROOT_CA_PEM` Dokploy variable can be deleted.
