# Research facts before asking the owner, in a shaping skill

On 2026-10-24 the owner answered about 43 shaping questions. Five came back as "read the official documentation" or "research this", and three as "I don't understand". The five were the heavy design questions. In three of them the research overturned the recommendation:

* a demo flag on three tables, where the documented practice is an ordinary reviewer account;
* a separate member record for retention, where GDPR Art. 17(3)(b) already exempts bookkeeping;
* moving Faker to devDependencies, which Nitro's bundling defeats.

**Root cause.** The grilling skill already says facts are the agent's job. The agent misclassified "what is the right or standard way" as a decision, when it has a documented answer in official docs, law, store guidelines or established vendors' practice. The "I don't understand" answers came from questions that used internal terms without stating the problem. This must hold for every agent, cloud builders included, so it goes in the repository and not in a local memory.

## Scope

* **New local skill** `.claude/skills/shaping/SKILL.md`, the entry point for shaping a Linear issue with the owner. Register it as `{"source": "local"}` in `.claude/skills.lock.json`. Before each round:
  1. Classify each candidate question. Only five kinds go to the owner: taste and wording users read; money and new vendors; risk appetite; scope and priority; business context only the owner has, such as hosting plans or account details.
  2. Everything else is a fact: what's correct, legal, documented or standard, or how established products do it. Research it first with `.claude/skills/research/SKILL.md` against primary sources (official docs, statutes, authorities, vendors' own docs). Record it with the date each source was read, as `docs/plans/<ID>.research.md` or an issue comment.
  3. Ask only the decision the research leaves open, with its sources. A recommendation names its source, or says "judgement, no source found".
  4. Each question opens with the problem in one plain sentence, with no internal terms.

  Then run the rounds in grilling's format (`.claude/skills/grilling/SKILL.md`, which stays pinned and unedited).
* `next-step` **§4 (Ask the owner):** apply the same classification before asking. A fact question follows the research rule in §2 ("Whatever the label") instead of going to the owner.
* `CLAUDE.md`**'s owner-decision bullet in Workflow:** add that a question with an answer in official docs, law or established practice is research, not a question for the owner, and point at the shaping skill. CLAUDE.md is at 3900 of 4000 characters, so rewrite it denser rather than cutting anything.
* `docs/agents/issue-tracker.md`**:** under "Ask the owner", the same one-line rule.
* Write all of it with `.claude/skills/writing-for-agents/SKILL.md`.

## Added 2026-10-25: record decisions so they can be audited, and the audit method

The shaping skill also covers: every shaped decision recorded with MADR and Nygard fields (drivers, options considered, choice with source or "judgement, no source found", accepted risks, revisit trigger; a reversal marks the old decision superseded and links the new one), and a `decision-audit` mode with six steps (find decisions, map before researching with the node fields, research depth-first per branch with verdicts `holds`, `questionable`, `wrong`, `owner-call`, `stale`, verify before reporting, return findings as text, report).
