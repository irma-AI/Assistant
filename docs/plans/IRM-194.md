# IRM-194: Add the rate-limited /api/v1/client-errors endpoint

`POST /api/v1/client-errors` takes only error name, message, stack, route pattern and app version (any other field is a 400), cuts the text, is rate limited, needs no login, and writes one `error` line with `service: "client"` through the log helper. The app and web client report unhandled errors to it. (Spec: IRM-137, decision 16.)

## Progress

- Endpoint `src/server/clientErrors.api.server.ts` and route `src/routes/api/v1/client-errors.ts`; event `client_error` added to the fixed list; reporter `src/api/clientErrors.ts`, wired in `src/routes/__root.tsx` (window error, unhandled rejection, error screen); `VITE_APP_VERSION` set in the Dockerfile build stage.
- Tests: `pnpm exec vitest run src/server/clientErrors.api.server.test.ts`; `logEveryEvent` now emits the line, so the IRM-100 test covers it; Playwright test in `e2e/smoke.spec.ts`.

## Decisions

- Rate limit is an in-process count per /24 (30 a minute, `CLIENT_ERROR_LIMIT`), not an audit row per report: the audit log is hash-chained and is no place for noise. Limit: a second instance doubles it.
- A request without a client IP gets 400, like the BankID start.
