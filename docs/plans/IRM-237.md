# Compress the JavaScript and CSS the server sends

Production sends `/assets/*.js` and `*.css` uncompressed even when the browser asks for gzip or brotli (main bundle 280 KB raw). Compress static assets at build time or in the reverse proxy; decide from the docs and record why. Acceptance: a request with `Accept-Encoding: br, gzip` gets the compressed file with the right `content-encoding`, one without gets the plain file; the release smoke test passes after deploy; `make check` passes.

## Progress

- Added `compressPublicAssets: true` to the `nitro()` options in `vite.config.ts`; `pnpm build` writes `.br` and `.gz` beside each asset.
- Ran `.output/server/index.mjs` locally and curled the main bundle: `br, gzip` gives `content-encoding: br` (77 KB), `gzip` gives gzip (89 KB), no header gives the plain 282 KB file; all carry or omit `vary: Accept-Encoding` correctly.

## Decisions

- Build time, not the proxy: it travels with the image, so it holds for every deploy and needs no Dokploy/Traefik setting that could drift. Nitro serves the precompressed file matching `Accept-Encoding`.
