# IRM-125: Invite members to an organisation with a single-use link

See the Linear issue (description with the 2026-10-25 decisions, plus its comments, which override it).

## Progress
- Migration 0008 `invites`; `invites.server.ts`; routes under `/api/v1/orgs/$orgId/invites` and `/api/v1/invites/$token` (public preview, session-only accept); `/app/invite/$token` page; invite UI in `/app`.
- Proof: `pnpm exec vitest run` (118 pass incl. `invites.server.test.ts`), `pnpm e2e` (invite spec passes on both iPhone projects).

## Decisions
- Accepting by someone who is already a member is a no-op that does not use the invite.
- The login panel is embedded in the invite page, and logging in there accepts at once; a same-device BankID return lands on `/app`, and reopening the link then offers "Gå med".
- Accept does not re-check the inviter's authority: the invite is the grant, and an admin can revoke it.
