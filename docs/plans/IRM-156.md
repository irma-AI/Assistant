# Notifications: in-app, email and push, with per-user preferences

Issue text: https://linear.app/petters/issue/IRM-156 (decisions 1-7 there: in-app and email in this issue, push is IRM-173, HostUp SMTP, per-organisation event table with RLS, recipients by permission, preferences per user and event type, agent writes the Swedish texts, SPF/DKIM/DMARC and an unsubscribe link).

## Progress

* Owner answered 2026-10-25: option 1 (user enters an address in settings and confirms it). IRM-133 and IRM-154 are Done.
* Built migration 0011 (users.email, email_verified_at, email_confirmations, notification_events/reads/deliveries with RLS, notification_preferences), `notifications.server.ts`, `notifications.delivery.server.ts` (job, 3 attempts, 1 and 2 minute backoff), API under `/api/v1/orgs/$orgId/notifications` and `/api/v1/me/{email,notifications}`, signed unsubscribe link, 90-day sweep, settings, confirm and notices pages.
* Proof: `pnpm exec vitest run` (src/server/notifications.server.test.ts, 9 tests, real PostgreSQL) and `pnpm e2e` (e2e/notifications.spec.ts, local SMTP capture server).

## Decisions

* No feature emits events yet; the registry in `src/api/notifications.ts` has `bank_consent_expiring` (mandatory) and `member_joined`. Features add types.
* Email is sent through nodemailer with `SMTP_URL` and `MAIL_FROM`; unset, deliveries fail and are recorded.
* Delivery rows are created with the event for members who have a confirmed address and email on; the job rechecks both at send time.
* Retention of events: 90 days (proposed, in records.md).
