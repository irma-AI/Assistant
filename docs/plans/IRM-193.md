# IRM-193: Add the log helper, request ID and per-request summary line

Build the logging described in `docs/observability.md` (spec: IRM-137). Builds on IRM-138.

* A small helper in `src/server/` writes one JSON object per line to stdout, with no logging library, and the fields and fixed `event` list from the spec.
* Every request, not only `/api/`, gets a `request_id`, sent back as the `x-request-id` header and shown on error screens.
* One summary line per request holds `route` (pattern, never the raw path), `status`, `duration_ms`, `request_id`, `user_id`, `org_id`, `outcome`, database time and each outside call's name and result. `/version` isn't logged.
* Step lines at `info` for session resolved, permission decision, each outside call and each write transaction, all with the `request_id`.
* Event lines for start-up, shutdown, migrations, jobs, login success and failure, access denial and unhandled errors; an error is logged once. Outside text is cut to a fixed length.
* The `service` field agrees with Vector's `service` stream field.

## Acceptance criteria

* A Vitest test against the real database shows one summary line per request with every field above, and the `x-request-id` header equal to its `request_id`.
* The IRM-100 test in `login.server.test.ts` covers every new event and finds no name, personnummer, token, raw path or full IP address.
* A divergent path (denied, cancelled) sets a field on the summary line, with no extra line at the branch.
* `docs/privacy/records.md` still matches what is logged.

## Decisions

- `recordAudit` is the one choke point that also writes the `login` and `access_denied` event lines.
