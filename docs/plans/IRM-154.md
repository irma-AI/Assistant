# Background jobs: scheduled and retried work (bank sync, tax-account sync, reminders, AI extraction)

Issue text: https://linear.app/petters/issue/IRM-154 (decisions: pg-boss in the existing Postgres, inside the app process, idempotent jobs, one key per organisation and type, tests against real Postgres).

## Progress

* Added `pg-boss` and `src/server/jobs.server.ts`: queues with retry and backoff, a dead-letter queue whose jobs are logged by id, and the login-attempt sweep as the first scheduled job (every 15 minutes).
* `startup.server.ts` starts the jobs in place of the old `setInterval` login sweep.
* `src/server/jobs.server.test.ts`: sweep job, retry after a forced failure, overlap guard (`pnpm exec vitest run src/server/jobs.server.test.ts`).

## Decisions

* Policy `stately` plus `singletonKey` gives the overlap guard; later jobs pass `<orgId>` as the key.
* Session and audit sweeps stay on `setInterval`; the issue only requires the login sweep to move first.
* Org scoping (`SET LOCAL`, RLS) arrives with the first job that touches organisation data (IRM-133); the login sweep has none.
