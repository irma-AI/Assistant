# IRM-162: Add Android's Material guidelines to DESIGN.md as one design shared with iOS

## Why

DESIGN.md's **Touch** section (IRM-160) follows Apple's Human Interface Guidelines only. The app also ships on Android through the same web code (Capacitor), and nothing says how Android's Material Design and Android quality guidelines apply. The owner wants **one design for both platforms, not two diverging ones**.

## Done when

* DESIGN.md's Touch section covers iOS and Android as one rule set. Where Apple and Google differ, it takes the rule that satisfies both, for example the larger tap target.
* It covers what Android adds: the system back button and back gesture, edge-to-edge layout, font scaling, dark theme, runtime permissions and notifications.
* No rule asks for a platform-specific look; a platform-specific behaviour (such as Android's system back) is stated as behaviour, not as a second design.
* Each rule names its source page, read on the date in `docs/plans/IRM-162.research.md`.

## Progress

- Rewrote DESIGN.md's Touch section as one rule set for both platforms; `grep -cE "Material|Android" DESIGN.md` shows the Android sources.
- `prettier --check DESIGN.md` passes.

## Decisions

- Conflicts resolved to the stricter rule: 48 px targets (Material, Android) over 44 pt (Apple); 12/24 px spacing (Apple) over 8 dp (Material); 17 px body (Apple) over 16 sp (Material).
- Both a visible on-screen back (needed on iOS) and Android's system back, doing the same thing. Android's quality rule against custom back prompts is read as banning "press back again to exit" prompts, not the top-bar back control that Material's top app bar also has.
- Material's auto-dismissing snackbar is allowed only as an echo of inline feedback, which satisfies both Material's own web accessibility note and Apple's advice against timed views.
