# IRM-151: Bookkeeping core

See the Linear issue (description plus its Decisions, which are the spec). Implements `docs/bookkeeping-foundations.md`.

## Progress
- Migration 0014 (fiscal years, BAS chart tables and seed, accounts, vouchers, lines, series counters, voucher documents, processing history, all with RLS and triggers), `src/api/bookkeeping.ts`, `src/server/bookkeeping.server.ts`, `src/server/bookkeeping.api.server.ts` and the routes under `/api/v1/orgs/$orgId/bookkeeping/`.
- Proof: `pnpm exec vitest run src/server/bookkeeping.server.test.ts` (all criteria).

## Decisions
- New permission `bookkeeping.manage`; every member reads the books.
- Posting is one UPDATE (draft to posted); the `vouchers_guard` trigger assigns the number from the series row, so the app cannot set it. The series table is reachable only through that SECURITY DEFINER function.
- Vouchers, lines and history reference the organisation with RESTRICT, so deleting an organisation or a user that holds books fails until the closing flow (IRM-92) exists.
- The chart seed copies all of BAS 2026 v1.1 (the "small starter set" in decision 4 was optional).
- No page yet: the Bokför preview screen and the voucher list are a follow-up UI issue. The API already returns the totals and `balanced` flag the preview needs.
- Documents are not date-locked separately; linking on posting sets `retain_until`, which freezes them.
