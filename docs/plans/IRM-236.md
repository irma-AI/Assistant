# IRM-236: Each screen's data starts loading on tap, not after the screen opens

## Why

Every in-app screen fetches its data in a `useEffect` (`useList`, `usePermissions` in `src/routes/app/org/$orgId/-call.ts`, and the shell's `GET /api/v1/orgs` in `src/ui/Shell.tsx`). The fetch starts only after the screen has rendered, and the screen shows "Laddar…" until it answers: every tap costs a full server round trip with nothing to show. The router already preloads on intent (`defaultPreload: 'intent'` in `src/router.tsx`), but no route has a loader, so there is nothing to preload. Found 2026-10-26.

## Scope

* Move each screen's data into its route's `loader` (Konto, Inställningar, Kunder, Medlemmar, Roller, Notiser, Företagsuppgifter, the invite screen), and the organisation list into the `/app` route, so the router fetches it on tap or hover and keeps it for screens already visited.
* After a change (save, delete, invite), the screen's data refreshes through the router (`router.invalidate` or the loader), not a separate fetch.
* The loading state's look is not in scope; that is the next issue.

## Acceptance criteria

* A Playwright test shows a screen's API request starts before the screen renders (on hover or touch of its link).
* Going back to a screen already visited shows its content with no loading state.
* After a save, the screen shows the saved data without a reload.
* The screens' existing e2e tests pass, and `make check` passes.

## Progress

- `e2e/preload.spec.ts` went red first (plain anchors, no loaders), then green: `pnpm exec playwright test e2e/preload.spec.ts` covers the first two criteria.
- Loaders on Konto, Inställningar, Kunder, Medlemmar, Roller, Notiser, Fakturor, Kvitton, Företagsuppgifter, the invite screen and the `/app` route (organisation list); saves call `router.invalidate()`. Third criterion: the existing specs that save and then read (customers, roles, notifications, company) pass.
- `make check` passes (all 106 e2e).

## Decisions

- Fakturor and Kvitton also move to loaders (same `useEffect` pattern, and Playwright specs cover them); the per-org invite widget on Organisation stays as is (not in scope).
- In-app anchors (`<a href>`) become router `Link`s, because a plain anchor reloads the page and never preloads.
- Class of bug: data fetched in an effect starts only after render. New screens use a route loader.
- TanStack Router 1.171 reloads a cached match in the foreground on re-entry even when it is fresh, so each loader route sets `shouldReload` through `src/ui/loaded.ts` (30 s window; `invalidate` still reloads at once). The window starts at the first revisit, not the load (a `shortcut:` comment says so).
- The invite screen has `gcTime: 0`: a one-time link is never shown from the cache.
