# IRM-16: Database foundation: Kysely, SQL migrations, generated types, real-DB tests

Database foundation (plan 2.7, 2.9, §8 step 8): PostgreSQL 16 with Kysely, plain .sql migrations run by one small provider (all pending in one transaction under Kysely's advisory lock) with its own test against the real database, types generated by kysely-codegen and checked by generate-check, Vitest in make check with a PostgreSQL service in ci, and a guard that a migration PR changes a test.

Acceptance criteria:
- The provider applies migrations in name order with several statements per file, and a failing migration applies none of the pending ones; both are tested against a real PostgreSQL.
- make generate rebuilds db.gen.ts and the route tree; generate-check fails when a committed copy is stale.
- ci runs the tests against a PostgreSQL 16 service pinned by digest.
- A PR that changes migrations/ without a test fails the pr-migration-test guard.

## Progress

- `src/server/migrate.server.ts` reads `migrations/*.sql` into Kysely's migrator; `src/server/migrate.server.test.ts` creates a fresh database per test on PostgreSQL 16.15 and passed both cases (order and multi-statement files; a broken second file leaves the first unapplied).
- `make generate` migrates `DATABASE_URL`, runs kysely-codegen and the production build; `generate-check` failed on an uncommitted `db.gen.ts` and passed once it was staged.
- Added `guards/pr-migration-test.jq` with fixtures; the self-test passes. `make check` passes.

## Decisions

- The route tree comes from the production build: `tsr generate` writes a Router-only tree without TanStack Start's types, so `@tanstack/router-cli` is removed.
- `createDb` takes the URL as an argument, so no module reads `process.env` at import time.
- squawk and the no-edit-after-ship rule for migrations come with the first real migration.
