# IRM-192: Intake PRs stall overnight as drafts

The intake sessions for IRM-126 (#117) and IRM-130 (#118) opened their PRs as drafts with `ci` and `policy` green. The merge queue never takes a draft, so they sat In Review, held intake slots, and nothing moved overnight. The #118 session wrote: "I've left it as a draft because my instructions say to open PRs that way." The cloud environment's session instructions say to create PRs as drafts.

Fix (owner, 2026-10-26): a PreToolUse hook refuses `draft: true` on the GitHub PR tools.

## Progress

- `.claude/hooks/draft-pr.sh` and its entry in `.claude/settings.json`.
- `bash .claude/hooks/test.sh`: "a draft PR is refused", "a ready PR is allowed", "a PR without the flag is allowed" pass.

## Decisions

- A hook rather than a line in CLAUDE.md or next-step: Claude Code's memory docs say CLAUDE.md is "context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook" (code.claude.com/docs/en/memory, read 2026-10-26).
- Accepted limit: `gh pr create --draft` bypasses the hook; in cloud `gh` is refused (next-step §3).
