# IRM-153: Company details per organisation

See the Linear issue (description plus its Decisions, which are the spec). Scope of this PR: manual entry, API and a plain settings page. Logo (IRM-155) and Bolagsverket auto-fill (IRM-168) are follow-ups by decision.

## Progress
- Migration 0013, `src/api/company.ts`, `src/server/company.server.ts`, GET/PUT `/api/v1/orgs/$orgId/company`, page `/app/org/$orgId/uppgifter`.
- Proof: `pnpm exec vitest run src/server/company.server.test.ts` (criteria 1-5); criterion 6 by `e2e/company.spec.ts` (saves details, reads back the VAT number).

## Decisions
- New table `company_details` (1:1 with `organisations`, cascade delete), so the unique org number needs no index on the existing table and a deleted organisation frees its number.
- Luhn, VAT number derivation and the fiscal-year rules live in `src/api/company.ts` (shared by server and form).
- The VAT-period turnover warning needs a turnover input the issue does not store; the owner moved it to IRM-210 (comment on IRM-153, 2026-10-26).
- `company_details` gets row level security, the `tenant` policy and the `assistant_app` grant like every tenant table, and the server reads and writes it through `inOrganisation`.
- The processing history (IRM-151) does not exist yet, so a fiscal year or accounting method change is audited with `detail.history = true`.
